# Задание: приём АГРЕГАТНОЙ отправки от склада (NET shipments)

> Дополнение к уже сделанной NET-интеграции (коммит `c9c903c`). Складская система
> `wh.net-delivery.com` при «Подготовить к отправке» шлёт **один** укрупнённый
> логистический заказ на уровне ОТПРАВКИ (не посылки). Реализуй приёмник.
> Пер-посылочный `/api/integration/net/orders` — **отладочный, выводим из игры** (см. §5).

## 0. Что уже согласовано и зафиксировано
- Один обычный **логистический заказ на отправку** (business_type=logistics), НЕ пер-посылочно.
- **Идемпотентность по `shipment_ref`** (повтор не плодит второй заказ).
- Заказ **участвует в учёте** — деньги реальные, выручка = суммарно оплачено клиентами.
- **Системный контрагент** для этих заказов: **«NET (розничные посылки)»**, код **`NET-RETAIL`**
  (создать один раз, переиспользовать).

## 1. Контракт (то, что WH реально шлёт — проверено вживую)
- **Endpoint:** `POST https://erp.net-delivery.com/api/integration/net/shipments`
- **Заголовок:** `Authorization: Token <net_inbound>` — **тот же токен**, что у `/net/orders`
  (`net_556d16d5cb49e142f145fd64ec482764b95ca33316dbde80`, запись `net_inbound` в `IntegrationSettings`).
- **Тело:**
  ```json
  {
    "shipment_ref": "SHP-000001",
    "created_at": "2026-08-27T20:05:00+00:00",
    "total_weight_kg": 0.8,
    "total_volume_m3": 0.0,
    "total_paid_rub": 370.0,
    "boxes_count": 1,
    "parcels_count": 1,
    "destinations": ["Москва"],
    "boxes": [
      { "box_code": "МОС-00001", "city": "Москва", "weight_kg": 0.8,
        "paid_rub": 370.0, "parcels_count": 1 }
    ]
  }
  ```
  (`total_volume_m3` может быть 0/отсутствовать — веса достаточно.)

## 2. Поведение
1. **Резолв контрагента** `NET-RETAIL` («NET (розничные посылки)») — найти или создать (юрлицо/служебный).
2. **Upsert заказа по `shipment_ref`:**
   - нет → создать `Order`: `business_type=logistics`, `source='net'`, `external_ref=shipment_ref`,
     `order_number = f"NET-{shipment_ref}"` (уникально), `client = NET-RETAIL`,
     `order_date = created_at.date()`, `tracking_number = shipment_ref`,
     `notes` = сводка (кол-во коробок/посылок, города).
   - есть → обновить агрегаты.
3. **Деньги/учёт (в отличие от пер-посылочного /net/orders):**
   - `excluded_from_accounting = false` — заказ **в учёте**.
   - Выручка/сумма заказа = `total_paid_rub` (в валюте компании; это уже итог, оплаченный клиентами).
   - Вес = `total_weight_kg` (в поле веса заказа/позиций), объём при наличии.
   - Разбивку по коробкам (`boxes[]`: город, вес, оплата, кол-во) сохранить как позиции заказа
     ИЛИ в JSON-поле/notes — на твоё усмотрение, но чтобы в карточке было видно состав по городам.
4. **НЕ пушить** этот заказ на irsway_site.
5. **Ответ:** `{ "ok": true, "shipment_ref": "...", "erp_order_number": "NET-SHP-000001", "created": true|false }`.
   Поле `erp_order_number` — WH его сохранит у себя.

## 3. Авторизация / ошибки
- Нет/неверный токен → `401`. Невалидное тело → `422`. Успех → `200/201`.
- Идемпотентно: повтор того же `shipment_ref` → `200`, `created:false`, тот же заказ, без дублей.

## 4. UI
- В разделе **NET** (уже есть фильтр `source=net`) эти заказы видны как обычные логистические.
  Тип «отправка» отличать по `external_ref`/`order_number` (`NET-SHP-…`) или добавить пометку.
- В карточке — состав по городам (из `boxes`).

## 5. Вывод из игры пер-посылочного `/net/orders`
- Пер-посылочный приём (`POST /api/integration/net/orders`, коммит `c9c903c`) был **отладочным**.
  После включения shipments — **отключить/удалить** его (или оставить возвращать 410/404), т.к. ERP
  пер-посылочные заказы больше не хранит.
- Со стороны app я **выключу** пер-посылочный пуш (`ERP_LIVE=false` в app), как только `/net/shipments`
  будет готов и вернёт `erp_order_number`. Сообщи, когда задеплоишь — сведём это одновременно.

## 6. Приёмочные проверки
1. `POST /net/shipments` (пример §1) → `201`, `created:true`, заказ `NET-SHP-000001`, контрагент `NET-RETAIL`,
   `source=net`, `excluded_from_accounting=false`, сумма 370 ₽, вес 0.8 кг, состав по коробкам виден.
2. Повтор того же `shipment_ref` → `200`, `created:false`, **второго заказа нет**.
3. Без токена / неверный → `401`.
4. Заказ **в учёте** (участвует в отчётах/выручке), в отличие от старого пер-посылочного.
5. На irsway ничего не ушло.

## 7. Что вернуть владельцу
- Подтверждение: `/net/shipments` задеплоен на прод, приёмка §6 зелёная, пер-посылочный `/net/orders` выведен.
- Тогда я на стороне WH ставлю `ERP_LIVE=true` (отправки пойдут реальными заказами) и на app выключаю
  пер-посылочный `ERP_LIVE=false`.
